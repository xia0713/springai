## 1. 核心知识点（40 分钟）

### 1.1 智能客服 / 智能问答：技术架构（分层讲）

```
┌─ 接入层：企微/钉钉/网页/工单系统嵌入（决定用户在哪用）
├─ 意图路由层：闲聊/知识问答/业务操作/投诉情绪 → 分流
├─ 知识层：RAG 知识库（标准问答）+ 业务数据查询（订单/工单，Function Calling）
├─ 生成层：LLM 生成 + 溯源标注 + 敏感词过滤
└─ 兜底层：置信度低/用户不满 → 转人工（带上下文，让人不用重问）
```

**讲方案的口诀：从上往下讲"用户怎么进来"，从下往上讲"答案怎么出去"，中间是你的技术护城河。**

**价值指标（客服场景的硬通货）：**
| 指标 | 定义 | 基准 |
|---|---|---|
| 自助解决率 | 机器人独立解决 / 总咨询量 | 行业 60-80% |
| 转人工率 | 转人工 / 总咨询量（越低越好，但要防强拦） | 与自助率互补 |
| 首次响应时间 | 用户提问到首次回复 | 秒级（人工是分钟级） |
| 满意度/采纳率 | 用户点赞 / 会话数 | >85% 及格 |

**成本估算的反直觉真相：token 是零头，人力才是大头。**

```
示例：日均 1000 次咨询 × 平均 3000 tokens/次（含检索上下文）= 300 万 tokens/天
按 ¥0.002/1K tokens → 日成本 6 元 → 月 ~180 元
而：开发 2 人月 + 知识库运营 0.5 人力/月 → 才是真正要汇报的成本
```

### 1.2 企业知识库：落地步骤 + 常见问题

**落地六步（讲方案时按这个顺序）：**

1. **选域切入**：选"咨询量大 + 答案标准化程度高 + 资料相对齐"的域先做（不要一上来全公司）
2. **资料盘点**：有哪些文档？质量如何（扫描件/格式乱是常态）？谁在维护？
3. **技术底座**：文档解析→清洗→分块→向量化→检索→生成（你 Day29-49 亲手搭的全链路直接讲）
4. **试点评测**：小范围上线 + 固定测试集量化效果（你 Day47 的评测体系直接讲）
5. **迭代扩域**：按测试集数据决定下一个域
6. **运营机制**：知识谁维护、多久更新、失效怎么审核 —— **这步决定项目生死**

**常见问题（每个都有对策，方案里必须写）：**

| 坑 | 对策 |
|---|---|
| 资料质量差（扫描件、表格截图） | 预算里预留清洗成本；OCR + 人工校对 |
| 检索不准 | 分块策略调优 + 混合检索 + 重排（Day34-38） |
| 没人维护，3 个月后变垃圾场 | 明确知识 Owner + 更新 SLA + 答案纠错入口 |
| 冷启动没人用 | 接入既有工作流（工单/IM 机器人），别做孤立网站 |
| 领导期望 100% 准确 | 试点期用测试集数据管理预期："当前 85%，路线图到 92%" |

### 1.3 两个场景的差异与选型

| | 智能客服 | 企业知识库 |
|---|---|---|
| 对话形态 | 多轮对话、要记上下文、有情绪 | 检索式问答为主，单轮居多 |
| 核心挑战 | 意图路由、兜底人工衔接 | 资料质量、检索精度、长期运营 |
| 价值指标 | 自助解决率、转人工率 | 使用率、命中率、知识维护时效 |
| 技术重心 | 对话记忆 + 意图分流 | 分块/检索优化 + 评测体系 |
| 你的现成资产 | Day56 智能助手 + Day59 记忆 | Day29-49 RAG 全链路 + Day47 评测 |

**选型结论：先做知识库（底座），客服是知识库 + 记忆 + 路由的扩展。** 你手里的资产正好按这个顺序长出来的 —— 方案叙事天然顺。

## 2. 实操作业（80 分钟）：《企业知识库落地方案》PPT 大纲

> 目标：五模块齐全的大纲，每页有 3-5 个要点。结合你的真实业务写（WOS 工单系统的客服知识库就是绝佳切入点 —— 问题件处理规范、导出模板操作手册、角色权限说明，都是"咨询量大 + 答案标准化"的典型资料）。

### 大纲模板（每页标题 + 要点）

```markdown
# 企业知识库落地方案 —— 以客服知识库为例

## 1. 背景与痛点（为什么做）
- 现状：客服/新人靠翻文档、问老员工，问题件处理规范等资料分散
- 量化痛点：日均 N 次重复咨询 × 平均耗时 N 分钟；新人上手周期 N 天
- 目标：常见问题自助解决率 ≥70%，新人上手周期缩短 50%

## 2. 技术架构（怎么做）
- 分层架构图：接入层 → 检索问答（RAG）→ 业务数据查询（Function Calling）→ 兜底人工
- 技术选型：Spring AI 1.0 + PgVector + qwen（说明为什么：Java 生态、私有化可行、成本可控）
- 已验证：内部已完成原型（RAG 链路 + 评测体系），Recall@5 达到 __%

## 3. 实施步骤（怎么落地）
- 一期（4 周）：客服规范域试点 —— 资料盘点/清洗/入库/评测
- 二期（4 周）：接入工作流（工单系统侧边栏）+ 业务数据查询
- 三期（持续）：扩域 + 知识运营机制（Owner/SLA/纠错入口）

## 4. 成本测算（花多少）
- 开发：2 人 × 2 月（可复用已有原型，实际可压缩）
- 运行：token 成本（算给他看：日均 N 次 × tokens × 单价）
- 运营：知识库管理员 0.5 人力/月（长期最大成本项）

## 5. 收益与 ROI（值不值）
- 硬收益：客服重复咨询节省 = 日均 N 次 × 自助率 70% × 单次 N 分钟 × 客服时薪
- 软收益：新人上手周期缩短、答复口径统一、7×24 可用
- ROI 公式：ROI = (年硬收益 - 年总成本) / 年总成本，试点后用真实数据回填
```

### 写作要求（三个硬要求）

1. **每处 N 必须用你猜的真实量级**（哪怕不准）—— 写"N 次"交差等于没写，数字才是方案
2. **第 2 页架构图直接用你自己项目的链路**（Day63 那张智能助手图裁剪版）—— 讲自己搭过的东西底气完全不同
3. **第 5 页的收益公式要有"回填"动作**（试点后用真实数据替换假设）—— 这是方案可信度的关键
