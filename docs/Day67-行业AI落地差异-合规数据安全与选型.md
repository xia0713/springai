## 0. 为什么行业差异不是"玄学"

同一个"智能客服"方案：电商团队能两周上线，金融团队评审三个月。**不是技术差距，是行业约束不同。** 看懂约束，才知道方案为什么长那样 —— 这是方案认知周的底层逻辑。

**分析框架：三个维度决定一个行业的 AI 落地形态。**

```
① 数据敏感度    → 决定部署形态（API 公有云 or 私有化）
② 容错成本      → 决定人机比例（AI 直接干 or AI 辅助人干）
③ 流程标准化程度 → 决定知识工程成本（RAG 直接上 or 先补知识）
```

## 1. 核心知识点（40 分钟）

### 1.1 五行业速写（三维度打分）

| 行业 | 数据敏感度 | 容错成本 | 标准化 | 典型硬约束 | 适合先做 |
|---|---|---|---|---|---|
| **金融** | 极高（监管/隐私） | 极高（资金） | 高 | 数据不出域、可解释、算法备案、审计留痕 | 内部知识库（不出域）、风控**辅助**（人审拍板） |
| **制造** | 中（工艺机密） | 高（产线/安全事故） | 中（老师傅经验未文档化） | OT/IT 网络隔离、机密不出厂 | 设备手册问答、维修工单助手（视觉质检是 CV 不是 LLM） |
| **电商** | 中（用户数据） | 中（资损/舆情） | 高 | 个保法、生成内容标识、大促峰值 SLA | 客服、文案生成、评论洞察 —— 迭代最快的行业 |
| **政务** | 极高 | 极高（舆情/责任） | 中 | 信创国产化栈、等保、不出域、答案必须可溯源 | 政策问答（私有化+引用条款原文）、材料辅助起草 |
| **物流/供应链**（你的行业） | 中（运单/地址是个人信息） | 中高（时效承诺/资损） | **高（SOP 文化强）** | 面单信息脱敏（行业常态）、跨境数据、链路数据分散多系统 | 工单分流、客服知识库、NL2SQL 运营分析（你的 3 场景） |

**读表方法：三个维度里最"极端"的那个，就是该行业方案的"第一约束"。** 金融的第一约束是数据不出域（模型选型被它锁死）；制造的第一约束是知识未文档化（项目前半段其实是知识工程）；物流的第一约束是个人信息合规 + 数据分散。

### 1.2 合规与数据安全的行业区别（讲清"为什么不一样"）

| 行业 | 为什么这么严 | 落到方案上的具体动作 |
|---|---|---|
| 金融 | 监管直接管模型（算法备案、可解释） | 私有化/行业云部署；决策链路留痕到"哪条规则触发了这个建议" |
| 政务 | 信创与等保是准入门槛 | 全栈国产化适配；答案引用政策原文条款（可溯源是硬要求） |
| 电商 | 个保法 + 平台规则 | 用户数据脱敏进模型；AI 生成内容按规定标识 |
| 制造 | 工艺参数是命根子 | 模型部署在厂内；知识库不含核心参数（分级） |
| 物流 | 个人信息保护（面单/地址）+ 数据多系统分散 | 查询结果按角色脱敏（客服看脱敏面单）；跨系统走 Function Calling 代理查询而不是搬数据 |

**任何行业通用的合规三件套（方案里都要有）：**
1. **数据分级分类**：哪些字段能进模型/向量库，先画表再开工
2. **脱敏与最小化**：进模型前脱敏、按需取数（不整库灌）
3. **审计留痕**：谁在何时问了什么、模型答了什么 —— 你 Day55 规范和 Day82 的审计设计就是它的实现

### 1.3 选型策略（速查表）

```
数据敏感度：低 → API 公有云（快、便宜）
            高 → 私有化/专有云/本地小模型（慢、贵，但过得了评审）
容错成本：  高 → AI 辅助人决策（人拍板）
            低 → AI 直接执行（效率最大）
标准化程度：高 → RAG 直接上
            低 → 先做知识沉淀（这本身就是项目，AI 是第二期）
```

**一句话总结：部署形态由敏感度锁死，人机比例由容错成本决定，知识工程量由标准化程度决定。** 面试聊"你们行业为什么这么选"，按这三个"由…决定"讲。

## 2. 实操作业（80 分钟）：你熟悉行业的 3 个核心痛点 + 方案

> 目标：选一个行业，输出 3 个痛点，每个配方案。**强烈建议写物流（你自己的）** —— 自检标准是"符合行业真实情况，不是纸上谈兵"，写自己亲眼见的才有底气。

### 硬要求：每个痛点必须有"亲眼看过的证据"

格式：

```markdown
## 痛点 1：<一句话痛点>
- 我见过的证据：<哪类工单/哪个流程/哪次事故/哪个群里的抱怨>（具体的！）
- 根因分析：<为什么会这样>
- AI 方案：<用什么能力解（对应你哪周学的）>
- 行业约束影响：<合规/数据安全在这个方案里怎么体现>
- 落地难度与切入：<先做哪一小块>
```

### 物流行业的 3 个候选痛点（参考校准，不是抄用）

**痛点 1：个人信息合规 vs 业务可用性的矛盾**
- 证据：面单/地址是个人信息，但客服处理问题件必须查；行业普遍做面单脱敏，客服看到的已是打码数据，部分场景还要找 IT 查明文
- 方案：分级授权 + 查询结果按角色脱敏（客服看脱敏版、组长看半脱敏）+ 查询留痕审计（Day82 能力）
- 约束体现：这正是物流行业"第一约束"直接塑形方案的例子

**痛点 2：知识分散在多系统，客服翻 3 个系统找答案**
- 证据：工单系统一套规范、TMS 一套状态、制度文档又一个入口
- 方案：统一知识库（制度/规范类，RAG）+ 跨系统实时查询走 Function Calling（工单/运单数据不搬不同步，按权限代理查）—— "静态知识入 RAG、动态数据走工具"的分工
- 约束体现：数据分散 → 不建数据大宽表（同步成本+合规风险），代理查询最小化取数

**痛点 3：高峰期（大促/春节）客服咨询洪峰**
- 证据：时效承诺类咨询在大促后暴增数倍，临时借调人手、响应质量下降
- 方案：自助问答承接标准化咨询（高峰弹性是 AI 的天然优势 —— 扩容模型实例比招人快几个量级）+ 异常主动通知减少被动咨询
- 约束体现：高峰 SLA 是电商/物流特有的约束，金融政务没有
