## 2. 核心：一份《知识库效果评估报告》该怎么写（40 分钟）

一份好的评估报告，不是把代码贴上去，而是回答清楚 5 个问题。用这 5 个问题当骨架，你的报告自然就有说服力。

### 2.1 骨架一：你要解决什么问题？（背景 + 目标）

一句话说清「为什么做这个知识库」：

```
背景：企业内部大量制度/物流/产品/政策文档散落各处，员工靠人肉翻找，效率低。
目标：搭建一个能「上传文档 → 语义检索 → 带依据问答」的知识库系统。
量化目标（呼应 Day42）：问答准确率提升 ≥ 20%，支持 100 份文档批量上传，多用户权限隔离。
```

**关键：目标必须可量化。** 「做一个知识库」不是目标，「准确率 ≥ X%」才是。

### 2.2 骨架二：你做了什么？（技术方案 + 架构）

用一张链路图讲清你的方案（这周你反复画过）：

```
上传 → Tika解析 → 清洗 → 分块(多策略) → 向量化 → PgVector入库
查询 → 查询改写 → 多路召回(向量+BM25) → 去重 → 重排序 → 生成(带依据)
工程化 → 异步批量 + 进度 + 重试 | docId增量更新 | owner权限隔离
```

**重点：突出「工程化」这层** —— 这是你和只会调 API 的人的区别。批量异步、增量更新、权限隔离、效果评估，这些才是「生产级」的门槛。

### 2.3 骨架三：效果怎么样？（数据，不是感觉）

这是报告的**灵魂**。用你 Day47 的评估结果填：

| 指标 | 数值 | 说明 |
|---|---|---|
| Recall@5 | __% | 召回能力（能找到） |
| Recall@1 | __% | 用户"看到的那一条"排第几 |
| 准确率 | __% | 生成答案对不对 |
| 幻觉率 | __% | 资料外问题会不会瞎编 |

**关键心法：用「对照」说话，不是「绝对值」。**

```
❌ 差：「我们的 Recall@5 是 85%」（没有参照，85% 好还是差不知道）
✅ 好：「纯向量基线 60%，加了混合检索+重排后到 85%，提升 25pp」
```

你 `ChunkTest` 的 V0→V4 对比，天生就是这种「对照」结构 —— 这就是它最值钱的地方，报告里一定要用上。

### 2.4 骨架四：踩了什么坑？（体现工程深度）

把你这一周真踩过的坑列出来（每个坑 = 一个「我懂生产」的证据）：

| 坑 | 你的解法 |
|---|---|
| `@Async` 自调用失效 | 拆独立 Bean 跨 Bean 调用 |
| MultipartFile 请求结束被删 | 请求线程内先 transferTo 落地 |
| `queryForObject` 查 0 行抛异常 | try/catch EmptyResultDataAccessException |
| `Filter.builder()` 在 1.0.3 不存在 | 改用 FilterExpressionBuilder |
| 文档重传导致重复向量 | docId + fileHash + 先删后插 |
| 权限过滤挡住检索 | 全链路 owner 过滤 |

**这些坑，面试官最想听。** 因为它们证明了你不是照着教程抄，是真做过。

### 2.5 骨架五：下一步怎么做？（体现规划）

报告结尾要有「接下来」，体现你不止步于 Demo：

```
短期：LLM-as-Judge 自动化评估、embedding 索引优化(当前 3072 维无索引)、
中期：权限升级为登录态(JWT)、评估报告自动化、Redis 进度持久化、
长期：接入监控告警、灰度发布。
```

## 3. 实操作业（80 分钟）—— 写出你自己的报告

> 目标：产出一份**属于你的**《知识库项目效果评估报告》。不追求长，追求「讲得清楚」。

### 步骤 1：跑出真实数字（先有数据，再写报告）

跑你 Day47 的两个评估，把数字记下来：

```bash
# 召回评估（Recall@1/3/5，V0→V4 对照）
./mvnw test -Dtest=ChunkTest

# 生成评估（准确率/幻觉率）
./mvnw test -Dtest=RagGenerationEval
```

> 注意：这两个测试依赖真实 pgvector + embedding。先确认本地 PG 和 embedding key 可用（你 `application.yaml` 里的 micuapi.ai）。

### 步骤 2：按「五骨架」写报告

新建 `docs/知识库效果评估报告.md`（或在你惯用的笔记里），按 §2 的 5 个骨架各写一段。**不用长，每段 3-5 行说清即可。** 重点把 §2.3 的「对照数据」和 §2.4 的「踩坑清单」填实。

### 步骤 3：给自己做一次「模拟面试」自检

对着报告，用嘴巴讲一遍（或写下来），检查能不能回答：

1. 「你这个知识库的**架构**是什么？」→ 能否一句话画清链路
2. 「效果**数据**是多少？怎么算的？」→ 能否说出 Recall/准确率/幻觉率的定义和数值
3. 「**优化**是从多少提到多少，做了啥？」→ 能否说 V0→V4 的增量
4. 「踩了什么**坑**？」→ 能否讲出至少 3 个坑和解法

**讲不清楚的地方，就是你的知识盲区，回头补。**
