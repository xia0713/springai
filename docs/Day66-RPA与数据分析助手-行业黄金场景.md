## 1. 核心知识点（40 分钟）

### 1.1 RPA+AI：让自动化从"结构化"扩展到"半结构化"

**传统 RPA 的本质**：模拟人操作 UI（点击/复制/填表），只适合**规则完全固定**的流程 —— 界面一改就崩，例外一多就废。

**AI 补上的一块**：RPA 搞不定的"理解"环节：

```
以前自动化不了的：读一封客户投诉邮件 → 判断问题类型 → 决定走哪个流程
AI 补齐后：       LLM 理解邮件语义 + 提取要素 → RPA/接口执行后续动作
```

**分工口诀：AI 负责"理解"，RPA/接口负责"执行"。** AI 别直接操作生产 UI（权限和稳定性都是灾难），理解完走 API。

| 适用行业 | 典型流程 |
|---|---|
| 财务 | 发票识别录入、对账差异初筛 |
| 人力 | 简历初筛、入职材料核对 |
| **物流** | 单据识别、异常件邮件/工单分类分流 |
| 电商 | 客服工单预处理、评价归类 |

**落地难点（方案里必须写）：**
1. **流程变更多** → UI 自动化维护成本失控；对策：优先走 API，RPA 只做没 API 的存量系统
2. **AI 操作生产系统** → 权限最小化 + 全程审计 + 高危动作人工确认（Day55 红线）
3. **"最后 10% 例外"占 80% 工作量** → 设计上就要有"转人工"出口，别追求 100% 自动化
4. **效果预期** → 演示 95% ≠ 生产 95%（脏数据的差距）

### 1.2 数据分析助手：三段递进（你已有第一段的原型）

```
① NL2SQL 问答（Day52 原型）：自然语言查数 —— 已验证可行
② 自动报表：定时查询 + LLM 生成"人话"解读 + 异常标注 —— 增量开发
③ 洞察生成：LLM 看多组数据，指出"值得关注什么、建议看什么方向" —— 价值最高也最需谨慎
```

**关键认知：洞察的价值不是算数（代码算得又快又准），是三件事 ——**
1. **翻译**：把数字变成业务判断（"问题件率环比升 2.3pp，主要来自 X 分拨"）
2. **指路**：告诉用户"接下来该看什么"（数据导航，省掉 80% 的摸索）
3. **兜底诚实**：口径不确定/数据缺失时明说，绝不硬解读

**落地难点：**
- **口径混乱是头号杀手**：同一个"销售额"三个部门三个定义 —— 口径表必须先于 NL2SQL（工具里写死，别让模型猜，Day52 的教训）
- **权限**：谁能问出谁的数据 → NL2SQL 按用户权限过滤表/行（Day52 三层防线扩展）
- **幻觉数字** → 洞察里每个数字必须能溯源到一条 SQL 结果

### 1.3 企业级落地的通用痛点（跨场景通杀，面试必备）

| 痛点 | 表现 | 对策 |
|---|---|---|
| 数据质量与口径 | 脏数据、定义打架 | 口径治理先行，纳入项目范围 |
| 期望管理 | 老板以为演示=生产 | 试点期用测试集数据说话（Day47） |
| 周期错配 | 要 3 个月见效，底座就要 2 月 | 分期：先窄场景出数字，再扩 |
| 组织配套 | 没人维护、没人背 KPI | 知识 Owner + 运营 SLA（Day64 生死题） |
| 长尾成本 | 最后 10% 边缘 case 吃掉预算 | 转人工出口 + 持续运营预算 |

### 参考答案（物流/工单系统视角 —— 校准用，不是抄用）

**场景 A：问题件工单智能分流与处理建议**
- **价值**：问题件工单量大、类型杂（破损/延误/地址异常…），人工判类型+定责任方+查规范占处理时长的大头；分流预处理可释放 30-50% 处理时间
- **技术方案**：LLM 分类（工单描述→类型/责任方初判）+ RAG 检索对应处理规范 + Function Calling 查运单数据 → 生成处理建议 → **人工确认后执行**（Day60 排障 Agent 的同构）
- **落地难度**：中。数据都在（工单库/运单库）；难点在历史工单标注做评测集、分类准确率的预期管理
- **为什么是它**：高频✓ 有数据✓ 容错可控（人工确认闸门）✓ 受益方明确（运营/客服）✓

**场景 B：运营数据 NL2SQL 问答报表**
- **价值**：运营/主管的取数需求挤占分析师排期；"工单量/问题件率/处理时长"这类查询高频且标准化；NL2SQL 问答可释放排期、决策响应从"等报表"变"即问即答"
- **技术方案**：NL2SQL（Day52 原型）+ 口径表写死进工具 + 按用户权限过滤 + 定时自动报表（LLM 生成人话解读）
- **落地难度**：低-中。原型已通；难点在口径治理和权限模型
- **为什么是它**：你已经有可运行原型 —— 方案里"已完成 POC"四个字价值千金

**场景 C：客服回复话术生成 + 合规质检**
- **价值**：客服回复占咨询处理时长的核心；统一口径 + 自动起草可缩短单均处理时长，新人直接产出合格回复
- **技术方案**：Day65 架构落地 —— RAG 检索规范/历史优秀回复（few-shot）→ 受约束生成（0.2）→ 规则+LLM 双层质检 → 客服修改后发送（人闸门）
- **落地难度**：中。生成质量依赖语料质量；难点在质检误杀率控制
- **为什么是它**：直接长在客服工作流里，用户天然存在（不愁冷启动）

> 注意：这三场景分别长在第 9 周（Agent）、第 8 周（NL2SQL）、第 10 周（生成+审核）的能力上 —— **好方案就是你已验证的能力 × 你业务的真实痛点**。
