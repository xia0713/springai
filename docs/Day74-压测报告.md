# Day 74 分层压测报告

> 测试时间：2026-09 · 环境：本机 Windows / Spring Boot 3.4.4 + Spring AI 1.0.3 / PostgreSQL(ai_db)
> 工具：Git Bash + curl（xargs -P 并行） · 口径：成功率 / avg / P50 / P95（P95 优先于平均值）
> 过关标准（学习计划）：50 并发下响应 ≤2s，成功率 ≥99%

---

## 一、总体结论

| 层 | 路径 | 并发 | 结果 | 判定 |
|---|---|---|---|---|
| **L1 系统底座** | 缓存命中路径 `/api/cost/chat` | 50×200 | **成功率 100%，P95=14ms** | ✅ 优秀 |
| **L2 DB 路径** | 向量检索 `/api/documents/vector/search` | 20×100 | **成功率 64%，P95=3.6s，P99=10.1s** | ❌ 不合格（根因：embedding 上游） |
| **L3 LLM 路径** | 智能问答 `/api/ai-gateway/chat` | 50×50 | **成功率 100%，P50=7.4s，P95=19.6s** | ⚠️ 可用但慢（根因：LLM 生成本身） |

**一句话结论：系统底座非常健康（P95=14ms）；两个外部上游（embedding 网关、LLM 生成）是全部延迟与失败的来源 —— 我们的代码层没有自伤，但缺对 embedding 上游的稳定性治理。**

## 二、逐层明细

### L1 系统底座（缓存命中路径）—— ✅ 优秀

| 指标 | 数值 |
|---|---|
| 总请求 / 成功 | 200 / 200（**100%**） |
| avg / P50 / P95 / P99 | 6ms / 5ms / **14ms** / 23ms |
| 缓存账本 | cacheHits 恰好 +200；tokensSavedByCache=16200=200×81（分毫不差） |

- 底座（Tomcat/网关/序列化/缓存）在 50 并发下毫无压力，远超 ≤2s 标准 143 倍。
- **账本自洽**证明 Day72 的统计口径可信 —— 这就是"能算清账"的底气。

### L2 DB 路径（向量检索）—— ❌ 根因在外部上游

| 指标 | 数值 |
|---|---|
| 总请求 / 成功 | 100 / 64（**64%**） |
| avg / P50 / P95 / P99 | 2.25s / 1.9s / **3.6s** / 10.1s |
| 最差样本 | 30s 超时（curl 000）、10.1s、4.9s |

**根因定位（三层排除法）：**
1. **单线程连续 3 次调用**：1.3s 成功 → 2.1s **500** → 15.2s 成功 —— 并发=1 也失败，排除并发因素
2. **embedding 直连端点连续 5 次**：3 次 500（60% 失败率）—— 锁定 micuapi embedding 上游抖动
3. PG 扫描本身无异常（成功请求里检索逻辑正常返回）

**次要发现**：延迟 P50 1.9s 里还包含每次检索前的一次 embedding 网络往返 —— 就算上游稳定，这条路径也到不了 L1 的毫秒级（查询向量化是必要成本）。

### L3 LLM 路径（智能问答）—— ⚠️ 可用但受生成速度限制

| 指标 | 数值 |
|---|---|
| 总请求 / 成功 | 50 / 50（**100%**） |
| avg / P50 / P95 | 9.1s / 7.4s / **19.6s** |
| 模型路由 | 50/50 全部走 SMALL（deepseek）—— 规则路由按预期工作 |

- 上游 ai-gateway（LLM）健康：50 并发零失败 —— 与 embedding 上游形成鲜明对比
- 延迟本质是 **LLM 生成时间**（50 个并发生成挤在上游排队），不是我们的代码
- 对照过关标准"≤2s"：**真问答路径达不到，且任何优化都改不了物理规律** —— 出路是缓存命中率、流式（TTFT 体感）、更小的模型，而不是压代码

## 四、P95 是什么（压测口径必懂）

**P95 = 95 分位响应时间**：把所有请求耗时从慢到快排序，第 95% 位置的值 —— 意思是"95% 的请求都比它快"。

**为什么不看平均值**（举例）：
```
100 个请求：95 个 0.1s，5 个 5s
平均 = (95×0.1 + 5×5) / 100 = 0.35s   ← 看起来很健康！
P95  = 5s                              ← 每 20 个用户就有 1 个等 5 秒
```
平均值把长尾"摊平"了，而用户骂的是那 5%。所以 SLA 都写 P95/P99。

> 标准：50 并发下响应 ≤2s，成功率 ≥99%

- **缓存命中路径**：✅ 通过（P95=14ms，成功率 100%）
